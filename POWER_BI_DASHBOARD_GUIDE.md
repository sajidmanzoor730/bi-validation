# Power BI Dashboard Build Guide

This guide describes the report to build from the curated synthetic data. The repository contains DAX measure definitions, but does **not** claim that a Power BI Desktop `.pbix` has been authored or published.

## 1. Load and model

1. Open Power BI Desktop.
2. Get Data → Text/CSV → select `BI_Validation_Clean.csv`.
3. Rename the imported table to `BI_Validation_Clean`.
4. Set `Created_Date` and `Resolved_Date` to Date/Time; `Week_Start` to Date; numeric fields to Whole Number or Decimal Number as appropriate.
5. Add the Calendar table and measures from `powerbi/BI_Validation_Measures.dax`.
6. If Created_Date includes a time component, create a date-only column in Power Query and relate it to Calendar[Date].
7. Mark Calendar as the model's date table.

## 2. Report pages

### Page 1 — Operations Overview
- KPI cards: Total Records, Completion Rate, SLA Achievement, Average Resolution Minutes, Average CSAT.
- Line chart: record volume by Calendar month.
- Bar chart: SLA achievement by Team.
- Stacked bar: status by Priority.
- Slicers: date, Team, Region, Priority, Channel.

### Page 2 — SLA & Resolution
- KPI cards: SLA Met, SLA Breached, SLA Achievement.
- Bar chart: SLA achievement by Priority and Team.
- Distribution: Resolution Minutes by Priority.
- Detail table: Record_ID, Team, Priority, Resolution Minutes, SLA Target, SLA Status.
- Call out that Pending and Unknown are excluded from the SLA achievement denominator.

### Page 3 — Quality & Customer Experience
- KPI cards: QA Pass Rate, Rework Rate, Average CSAT.
- Bar charts: QA Pass Rate by Team; Rework Rate by Category.
- Scatter chart: QA Score vs CSAT, with Team as legend.
- Breakdown: repeat and escalated records by Root Cause.

### Page 4 — Data Quality
- KPI cards: Valid Data Rate, total records, corrected / standardized / nulled counts.
- Bar chart: row-level issue findings by Issue Type using the issue log.
- Table: Record_ID, Issue_Type, Affected_Field, Original_Value.
- Explain that one record may have multiple issue findings; findings are not distinct affected-record counts.

## 3. Design guidance

- Use a consistent 16:9 canvas and restrained palette.
- Put the reporting period and synthetic-data disclaimer in the footer.
- Use clear units: minutes, score out of 5, percentages.
- Avoid 3D charts and unnecessary gauges.
- Use conditional formatting for SLA and data-quality exceptions.
- Include a "Last refreshed" timestamp only when it is genuinely generated by the report refresh.

## 4. KPI reconciliation

Run:

```bash
python reconcile_kpis.py
```

This writes `outputs/python_kpi_baseline.csv`. After building the report, export a two-column CSV from Power BI with columns `Metric` and `PowerBI_Value`, using the metric names in the Python baseline. Then run:

```bash
python reconcile_kpis.py --powerbi-export path/to/powerbi_kpis.csv
```

The comparison reports Python value, Power BI value, variance, and PASS/FAIL using the tolerance documented in the script. Do not claim cross-tool reconciliation until an actual Power BI export has been compared successfully.
